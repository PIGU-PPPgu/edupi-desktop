EduPi Desktop 0.3.76 macOS Apple Silicon 技术试用候选，Release 保持 Draft。

`.75` 的 App 与 DMG 均获 Apple 公证 Accepted，但 DMG 装订票据时 Apple CloudKit 连接中断，整轮仍记失败且未安装。现在仅为这一票据端点的已观察断连增加最多三次装订尝试；票据无效、签名错误、未知网络错误仍立即失败，最终票据验证、签名和 Gatekeeper 门不变。原 `.75` Draft 与身份保留，不重跑或混用资产。

本轮固定 Core 已合并的删除隐私收口：已删除学生的姓名不再经无 ID 全局记忆、旧记忆写入或历史工具结果回到模型；不相关的已审核偏好保留。Desktop 真实 SDK 已验证删除前可见、删除后拒绝及 Core/SDK 冷重启后的历史防回生。损坏旧主动提醒账本与独立内部到期工作隔离；旧飞书外发结算不明和混合收件人没有因此解决，不开启外发。`.74` 在完成签名前因该新固定 handoff 取消，原 tag 与无资产 Draft 保留，不重用资产。

真实 HFS+ 卷实测发现系统 `df` 的结构化类型值带一个格式空格；Core 只处理该精确填充，其他空白、异常名称与未知文件系统仍拒绝。根准备、指纹回读、嵌套文件证明和符号链接拒绝已在同一合成 HFS+ 卷验证；不是物理 HFS 磁盘或安装 App 在 HFS 上的验收。`.73` 已在打包前取消，保留原 tag 和无资产 Draft，不重跑或改写。

Core 改为读取系统原生文件系统名称来验证 APFS/HFS，不再把 macOS 动态注册编号当成固定类型；目录、挂载点、数据库和授权身份仍逐项核对，不迁移或静默重绑定已有授权。前一 `.72` 在配对根校验阶段失败且没有生成安装资产，原失败未复现，不把本次可移植性修复冒充已证实的原故障归因。

本轮在 Core 已合并的来源删除、事实修订和课次修复上，补齐普通对话的可信记忆召回、三域草稿执行与审核后评价、家长收件人明确确认、本地用量同意及持久队列。Core 精确提交、Runtime schema 和双组件清单以包内兼容清单为准。真实对话只有在 Core 肯定捕获后才发送 Pi；规范化命令身份不再受 JSON 字段顺序影响。

本轮只构建 macOS Apple Silicon。Windows 构建和原生检查按用户指令暂缓，Linux 不纳入本次候选；没有三平台同轮资产证明，不公开 Release、不更新七平台 updater feed。当前公开安装版仍为 v0.3.70。Mac 签名、公证、包内 Core 身份和隔离根安装结果分别按实际证据记录。

仓库级 Rust 审计对 `zip 4.6.1` 报出三项漏洞，其中一项严重、一项高危；该版本由 Tauri updater 的 Windows 目标依赖带入锁文件。此候选仅在 Mac 目标依赖闭包排除旧版 `zip` 后才继续签名；仓库级审计仍失败，不能据 Mac 检查宣称 Windows 安全或发布资格。待上游提供已发布修复并完成全平台验证后再处理正式发布。
