# EduPi 产品模型在 Desktop 的落点

EduPi Desktop 是教师日常工作的统一入口，也是 EduPi Agent 的可视化执行面。它读取 EduPi 安全存储中的同一份事实、任务、证据和审核记录，不建立第二套教育数据。

## 一级入口

| 入口 | 教师要完成的事 | 读取的事实 |
| --- | --- | --- |
| AI 协作 | 发起或继续一段自由协作 | Pi 会话与当前教育上下文 |
| 今天 | 看 EduPi 已准备的简报、现在该判断的工作和接下来的节点 | 日简报、已到触发日的任务、当前周、近期洞察 |
| 教学 | 从学情与材料形成下一课调整并留痕 | 学科知识状态、教学记忆、教学任务、产物 |
| 班级 | 继续观察学生、闭环跟进并回看家校联系 | 学生画像、学习模式、跟进任务、家长画像 |
| 学期 | 对齐当前周、课程节奏和完整每周校历 | 课程表、校历 |
| 教育记忆 | 查看 EduPi 当前记住的教师事实 | 学期、班级、教学、偏好和学校记忆；提醒投递日志不进入主视图 |
| 观察与洞察 | 检查已浮出判断、弱信号和仍在酝酿的候选 | 潜意识信号、可追溯洞察、证据 ID；重复记录按主题聚合 |
| 成长 | 回看日常沉淀、已确认成果和 EduPi 学习候选 | 日/周报、洞察/整理记录、产物、主题候选与证据状态 |
| 材料 | 找到原始材料及其来源 | 材料任务、证据引用 |
| 待我确认 | 接受、修改、暂缓、拒绝或回滚当前已到触发日的工作 | 候选任务与审核历史 |

“学生档案”“教学任务”和“教学产物”仍是可链接的内部页面，用于从工作域进入具体对象，不再与“班级/教学/成长”重复占用一级导航。未来周次的准备任务保留在任务和学期视图，未到触发日不会挤入“今天”或“待我确认”。

## 统一工作闭环

教学与班主任工作共用 `观察 → 准备 → 审核 → 留痕`。界面只根据安全存储已有内容显示进度：没有 `deliverables` 时不生成占位产物；推断内容保持候选状态；外发始终关闭；写回前必须由教师审核。

任务与 Pi 会话通过任务 ID 持久绑定。教师从任务进入 Agent 后继续同一会话，重启后仍可恢复；AI 可通过 `edupi_app_control` 打开 EduPi 内部视图和任务。全局操作系统控制由独立的 `edupi_computer_use` 承担，默认关闭，并经过系统权限、教师逐次确认、快照防重放、审计和急停边界。

## 设计依据

本轮映射来自 EduPi 仓库的 `README.md`、`PRODUCT_VISION.md`、`L5_CONSCIOUSNESS_DESIGN.md`、`LOOP_CONTRACT.md`、`RHYTHM_PLANNER.md`、`EDUPI_DESKTOP_INTEGRATION_BOUNDARY.md`、`EDUPI_EDUCATION_MODULE_SKELETON.md`、`PRODUCT_GAP_ANALYSIS.md` 和教育工作流矩阵。原 EduPi 的差异点不是更多功能菜单，而是“主动搭档 + 长期记忆体 + 可验证成长”；Desktop 因而同时呈现教师工作和长期积累，但不把内部“意识层”包装成玄学页面，也不把重复提醒日志当成教育事实。观察、候选、证据、审核和下一轮变化都保持可检查。
