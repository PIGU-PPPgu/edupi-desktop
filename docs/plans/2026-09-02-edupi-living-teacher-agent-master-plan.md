# EduPi Living Teacher Agent 总计划

日期：2026-09-02  
主目标：让 EduPi 提前完成教师行事历上的可逆工作，Desktop 负责把这一过程变得可见、可改、可接管。

## 1. 最终产品

老师不再从模块菜单出发，而是从一天的真实工作出发：

```text
07:30  今天：EduPi 已准备 3 件，1 件需确认
课前    教学：本节目标、班级薄弱点、材料和课堂策略已聚合
课后    班级：一句口述进入学生观察，重复模式自动浮出
下午    日程：新通知进入校历，后续工作包自动重排
下班前  待我确认：老师集中修改、接受或暂缓，不再逐项从零制作
夜间    成长：当天产物和反馈进入可追溯沉淀，改变下一轮准备
```

Chat 永远保留在最顶部，负责自由协作、口述和复杂修改；简单事实继续原位人工编辑。教师不需要理解模型、Agent、prompt、六层架构或桥接协议。

## 2. 成功指标

发布后不以页面数量验收，使用六个产品指标：

| 指标 | 定义 | 首轮目标 |
| --- | --- | --- |
| 提前完成率 | 可信工作节点中，在教师主动开始前已达 `draft_ready` 的比例 | 真实试用建立基线后连续提升 |
| 只需确认率 | 教师接受或轻改即可使用的候选产物比例 | 不设虚假目标，按场景分层统计 |
| 遗漏率 | 校历/通知中应生成但未生成工作包的比例 | 每个失败可追溯 |
| 无效打扰率 | 教师拒绝、抑制或认为不值得提醒的主动项比例 | 每周下降 |
| 证据完整率 | 可回到来源、输入快照、任务、产物版本和回执的结果比例 | 100% |
| 连续性 | 重启、升级、断网恢复后同一 work case 状态一致 | 100% 关键闭环 |

学生与家长相关功能另设边界指标：未经授权外发为 0；AI 诊断性定性为 0。

## 3. 产品骨架

### 今天

只回答三件事：EduPi 已经做完什么、现在需要老师判断什么、接下来七天什么会自动开始。默认不显示未来整学期清单。

### 工作区

成为所有运行中 `work_case` 的任务板。列仍是待开始、进行中、待确认、已完成，但卡片展示真实触发、准备截止、产物和阻塞，不展示代码仓库概念。

### 教学

以“下一节课”为核心，不再堆统计卡片。一个教学工作面包含课程、班级、教学重点、近期错因、关联材料、EduPi 准备状态、课后观察和产物版本。

### 班级

主界面是可扫描的学生名单；点击学生从右侧打开档案、观察、跟进、家校记录和 EduPi 记忆。教师可以手动修改，也可以交给 AI 协作。导入和按时间节点导出是正式闭环。

### 日程

保留汇总 / 校历 / 课程表切换，并提供月、周、日与课表网格。日程、课程和工作包均可点击、原位在右侧编辑、删除或继续协作。任何文件、图片或口述形成新事件后立即重算相关工作。

### 教育记忆

二级导航先选学期，再选学生与班级、教学、教师偏好、学校事务等类别；主区域分页展示该类别的内容。记忆详情提供手动修改、AI 协作、版本、来源、被哪些任务使用和删除/恢复。

### 观察与洞察

使用 Notion/Supabase 式数据库视图。先按观察、教学模式、学生跟进、班级趋势、家校线索、跨域洞察分类，再按学期、班级、学生、学科、状态、证据筛选。洞察必须显示从酝酿到浮出的证据路径。

### 成长

明确区分三条成长线：学生成长、教师专业成长、EduPi 学习与修正。默认进入教师专业成长；EduPi 自身候选必须标注证据级别、试用状态和是否真正影响下一轮。

### 材料

二级分类就是页面主标题。材料支持预览、补充、手动编辑、AI 协作、来源追踪、关联任务、版本和删除/恢复。材料不是文件仓库，而是工作 case 的证据与产物入口。

### 待我确认

使用小型审核看板：任务、观察、记忆、外发草稿。一次进入一个对象，显示“为什么现在出现、依据是什么、我可以做什么”。审核流程进入右侧时间线，不再占据主页面横向大步骤条。

## 4. 十二个可合并阶段

每阶段都形成 Core checkpoint、Desktop checkpoint、配对 E2、真实浏览器证据和独立 PR。阶段间按 work case 合同连接，不同时重写所有页面。

### E0：风险与发布基线 — 已完成

- 六类可编辑教育对象支持稳定 ID 软删除；来源更新不复活对象。
- 已接入材料进入相同删除与审计链路。
- 丢失响应重试可对账，来源文件不被物理擦除。
- Apple Silicon DMG 真实构建、挂载、启动；Windows x64/NSIS 配置和路径约束验证。

验证：六对象真实 E2、Core 全套、Desktop 类型/定向测试、DMG 冷启动和退出清理。

### E1：统一 work case 与事件总线

Core 新增稳定的 `work_case_id`、`trigger_id`、`execution_revision`、`artifact_revision` 和 `transition` 投影，贯通日程、任务、材料、学生跟进与审核。Desktop 只消费 transition，不自行猜状态。

验证：同一 case 从五个入口打开得到同一身份；乱序、重放、重启、来源变更不产生 ghost；旧 Desktop 对新增字段保持兼容。

### E2：Desktop 活动流与对象时间线

建立轻量活动流：侧栏只显示运行/待确认数量，今天与工作区展示真实流动；所有详情抽屉复用对象时间线。动画绑定 transition，并支持减少动态效果。

验证：queued → running → draft_ready → reviewed 的每次可见变化都有 Core transition；刷新不会重复播放；无状态变化无动画。

### E3：教学前自动准备

基于课程表、当前教学进度、教学重点、班级薄弱点和材料，为下一节课自动生成：目标核对、易错点、课堂策略、材料缺口和课后观察入口。教学重点既可对话/口述导入，也可人工维护。

验证：真实课表中六节数学课均形成稳定 occurrence；同一节课重复运行不重复；教师改重点后只重做受影响部分；来源与版本完整。

### E4：课后口述到教学记忆

教师一句口述被拆成学生事实、课堂观察、待验证假设和下一课调整候选。简单事实可手工修改，复杂调整进入 Chat；不把观察自动写成学生定性。

验证：多学生同一句输入正确拆分；重复口述幂等；冲突形成候选；确认后教学页、学生档案和下一课准备同步更新。

### E5：班主任日常闭环

覆盖学生事件跟进、家长沟通准备、班会/安全活动、缺交与表扬记录。所有外发仅生成草稿；专业判断和特殊关注保持人工 gate。

验证：一个学生事件从观察到跟进结果闭环；家长草稿引用真实历史但不泄露其他学生；未经确认外发为 0。

### E6：学校事务与材料包

将会议、检查、计划、总结、家长会、迎检台账等映射为标准工作包。日常证据持续沉淀，临近节点直接组装初稿，不再到期突击搜集。

验证：至少三类真实学校事务从通知进入日历、工作包、产物与审核；缺材料明确显示缺口，不能编造已完成。

### E7：连续潜意识与低打扰注意系统

潜意识从“每天做梦一次”改为事件驱动 + 低优先级持续循环。观察按显著性、紧迫性、证据质量和教师抑制策略竞争进入有限工作区；没有价值则保持安静。

验证：两个候选竞争时排序可解释；低置信度进入澄清/hold；教师拒绝改变下一周期；重启恢复；无 evidence 不浮出。

### E8：教育记忆图与可编辑历史

建立学期、学校、班级、学生、家长、学科、课程、教学策略和教师偏好的关系索引；不是一次性摘要。所有人工修改、AI 候选、冲突和使用记录都有版本。

验证：跨会话问“我是谁、教什么、这个学生之前怎样”命中同一事实；修改后旧版本可见；删除后不召回；恢复后重新参与检索。

### E9：全学科能力包

把 44 个场景从 prompt 名单改为有输入契约、输出契约、证据要求、失败状态和真实样例的教育能力包。优先数学教学、班主任、安全教育和家校沟通；知识图谱走可替换接口。

验证：每个上线能力都有黄金集与失败样例；路由 Top-1/Top-3、教师可用率和修改量可度量；未通过的能力不进入自动执行。

### E10：教师反馈驱动的策略学习

统计教师接受、修改、拒绝、抑制、提前量调整与产物使用结果，形成可回滚 policy candidate。候选先影子运行，再在 held-out 教育任务比较，最后由教师确认晋级。

验证：不能用模型自评晋级；reload 后证明加载；错误可回滚；策略变化能在下一同类 case 中被观察。

### E11：跨设备交付与本地身体

Desktop 常驻运行、快捷入口、系统通知、任务/产物直达、升级恢复继续完善；手机与飞书只作为交付通道，不复制 Core 教育状态。

验证：后台完成通知可直达对象；离线后重连不重复；签名升级保留工作状态；真实 Feishu E4 必须有 inbound/outbound message ID。

### E12：真实教师 E5 与规模化发布

至少三位不同角色教师使用真实材料，冻结 held-out 任务，记录节省时间、遗漏、接受/修改/拒绝、打扰和错误。独立评价，不以 demo 成功代替真实效果。

验证：连续四周；重启与升级覆盖；失败样例与撤回记录保留；明确哪些工作不应自动化。

## 5. 下一批立刻执行的三个 PR

### PR A — Core Flow Contract v1

新增 work case/transition 投影，先覆盖一个校历节点自动准备链；不修改所有业务存储。  
验证：fixture + restart + replay + stale-source + component manifest。

### PR B — Desktop Living Flow v1

工作区和今天消费 transition，复用统一对象时间线；把真实运行、完成、记忆吸收做成克制动效。  
验证：浏览器状态转换、减少动态效果、刷新不重播、0 console error。

### PR C — Teaching Before-Class v1

把吴老师的新课表作为真实基准，完成“下一节课 → 教学重点 → 班级学情 → 材料 → 准备产物 → 教师确认”。  
验证：六个课程 occurrence、模型可用与不可用路径、产物来源、教师修改、restart/replay。

这三个 PR 完成后，EduPi Desktop 才会第一次不只是“显示 EduPi 的数据”，而是让老师直接看见 EduPi 的六层正在为下一节课流动。

## 6. 工程与发布节奏

- 每个阶段先写 paired contract，再分别实现 Core 与 Desktop。
- Core 先合并，Desktop 固定精确 commit 与 component manifest。
- 每阶段必须有一条真实教师输入 E2；模型不可用单独记为 unavailable。
- 每阶段使用 checkpoint/PR，主分支始终可运行、可回滚。
- 不在正在运行的开发工作树执行桌面构建。
- 外发、认证、隐私和更新签名仍使用独立发布 gate。

## 7. 当前已知风险

- 真正的“提前做完”仍依赖 provider 的稳定性与真实教师材料基准，不能由单测代替。
- Windows x64 NSIS 已由 GitHub `windows-latest` runner 构建并上传预览 artifact；干净 Windows 用户环境的安装、首启、更新与卸载仍未实机验收。
- 当前 DMG 是 ad-hoc 签名预览包，未 notarize，也不是 updater 基线。
- Core 的部分 L4/L5 能力仍只有隔离证据；Desktop 不应把它们包装成已完成能力。
- 稳定软删除已解决复活风险，但恢复操作还需作为显式 Core command 和 UI 闭环进入 E1/E2。
