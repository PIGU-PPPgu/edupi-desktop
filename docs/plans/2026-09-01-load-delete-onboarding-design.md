# EduPi 上线前加载、删除与新手引导

## 目标

1. 教师进入工作台后尽快看到可操作界面，避免重复读取同一份教育投影。
2. 所有已经支持手动修改或 AI 协作的核心对象，都有一致的删除入口。
3. 新手教程真正带教师完成模型、身份、校历课表和第一份材料，而不是只展示说明文字。

## 加载基线

2026-09-01 本地教学页重载：

- 可操作标题出现：1313ms
- `/api/edupi/onboarding`：631ms
- `/api/edupi/education`：506ms
- 首屏存在并发的重复教育投影请求；后台完成监控与教育工作台各自读取一次 Core 快照。

采用浏览器端仅限“正在进行中的请求合并”：同一时刻多个消费者共享一个 `/api/edupi/workspace` Promise，请求结束后立即释放，不引入陈旧缓存。目标是首屏教育投影从两次 Core 进程调用降为一次，并记录优化后的同口径数据。

实现后进一步把教育数据与教师上下文合并为 `/api/edupi/workspace`，两者从同一份 Core 快照投影。稳定热启动复测：

- 可操作标题出现：839ms（原 1313ms，降低约 36%）
- `/api/edupi/workspace`：215ms
- 首屏不再请求 `/api/edupi/onboarding` 与 `/api/edupi/education` 两条重复 Core 快照链路

Next.js 开发模式首次编译仍会产生一次性冷启动波动；上述对比使用相同页面的稳定热启动口径。

## 统一删除

删除由 Core 拥有，Desktop 不直接修改 `.edupi` JSON。

首批对象：

- 校历节点
- 课程表安排
- 教育记忆
- 学生档案
- 教师任务

Core 使用软删除记录：目标从教育投影中消失，底层来源事实不被物理擦除；删除记录包含目标类型、目标 ID、当时内容指纹、教师、时间和备注。目标来源发生变化时，旧删除记录不会吞掉新版本。

Desktop 统一调用 `DELETE /api/edupi/entities/[kind]/[id]`。按钮只在 Core 声明支持且目标有稳定 ID 时出现；点击后显示包含对象名称的确认，成功后使用 Core 返回的新教育投影刷新当前页面。AI 协作仍可帮助判断，但实际删除由教师按钮确认。

## 新手教程

教程改成不遮挡工作区的紧凑教练卡，共五步：

1. 连接 AI 模型
2. 填写教师资料
3. 导入校历与课表
4. 上传第一份材料
5. 进入今天

每个设置步骤第一次点击打开真实目标页面，按钮随后变为“完成，下一步”。教程继续停留在页面右下角，教师可以操作目标页面，不再因为教程被隐藏而失去方向。Escape 或“稍后再说”结束本轮，帮助入口可重新打开。

## 验收

- 首屏同一时刻最多一个教育投影请求，优化后重新记录可操作时间与接口耗时。
- 五类对象的删除都经过 Core、具有审计记录、支持幂等且能抵抗陈旧目标。
- 日程详情、记忆、学生档案和任务详情都出现一致的删除操作。
- 新手教程能依次打开模型、教师资料、日程、材料和今天，且不阻塞目标页面交互。
- 全量测试、类型检查、Lint、Core 合约测试和真实浏览器验收通过。
