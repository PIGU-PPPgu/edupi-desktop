# 学生教育网络与桌面端下一轮计划

日期：2026-09-05。状态：设计已记录，图谱功能尚未实现。

## 产品目标

老师日常与 EduPi 对话，就能持续积累每个学生的学习证据和同伴互动；这些记录影响下一节课的准备、分层练习和后续跟进。Desktop 提供查看、修改、删除与来源回溯。延续既定的交互修复、课前准备、首次使用三个阶段，将原总计划 E4/E8 提前穿插到课前准备中。

## 统一网络，两个默认视图

### 学习网络

教材知识结构共享；每个学生的观察与学习进展单独关联。节点：学生、知识点、习题、课程、材料；关系：前置知识、涉及知识点、学习证据、采用的教学方法。默认展示选中学生和近期相关知识点，点击再展开前置概念及来源。

掌握情况采用有证据的文字状态，例如“尚无记录”“近期仍有困难”“本次独立完成”。一次帮助同学、一次答对或一次错误，不直接替代长期掌握判断。跨学科逐步导入具有教材版本和来源的知识结构。

### 同伴互动

记录具体、有时间的帮助、合作、冲突和修复事件，保存发起者与参与者。默认按本班、本学期和时间窗口查询；不同性质的事件并存，不互相覆盖。长期关系只由明确记录支持，不能由共同出现在一段文字里自动生成“朋友”“敌对”等结论。

无记录的学生正常保留在名单中；不解释为孤立，不生成受欢迎程度排名。多人小组活动保存为一个多人事件，不自动扩展成所有人两两之间的关系。教师内部查看；家校产物不自动附带其他学生的个人图谱。

## 对话闭环

示例输入：“今天甲还是把移项符号弄错了，乙给他讲了一遍，之后甲自己做对了两题。”

1. 保留该条教师消息为来源，解析学校、班级、学期及两名学生的身份。
2. 形成甲的两条学习观察：先出错，后在讲解后独立完成两题。不能抹去先前困难。
3. 形成乙帮助甲的互动事件，主题关联移项；不据此宣称乙已掌握该知识点。
4. Core 持久化后，桌面出现简短“已记录”反馈，学生档案可查看对应证据。
5. 下一次相关备课检索这些记录，准备巩固练习并列出使用的依据。
6. 教师修订或删除后，图谱与后续检索同步更新；已生成材料标为来源已变化，按需重新准备。

明确的教师陈述按陈述保存；AI 对长期规律的推断单独标记，存在歧义才请求澄清。同名、代词指向不明时保留原记录，不猜学生身份。模型未完成或失败时保留可重试状态，不能显示“已记住”。

## Core 与 Desktop 的责任

Core 持有稳定的学生身份、概念身份、事件、时间、来源消息、证据和修订历史。学生用稳定 ID 关联，姓名用于显示；跨班同名不能合并。涉及旧姓名键的迁移必须有保留原数据的验证。

图谱是现有事实的可重建索引，不另建一套 Desktop 真相存储。第一版复用现有存储，查询按班级、学期、学生、主题和时间限定范围，分页返回邻居；无需先部署独立图数据库。

记录最小字段：record_id、kind、scope、参与学生及角色、concept_ids、发生时间/时间精度、recorded_at、source_message_id、evidence_ids、陈述或推断状态、revision、替代/撤回状态。具体 API 在 Core 实现前结合存储约定定稿，Desktop 不预先猜字段。

删除原始记录或学生后，图索引与 AI 检索同时排除相关内容；重放旧消息不复活。原文中的否定、假设、引用和纠正必须保留语义，不能一律当事实。

## 桌面呈现

- 班级主界面：名单 / 学习网络 / 同伴互动切换，保留当前班级和学期。
- 学生右侧档案：个人资料、学习证据、同伴互动；提供手动编辑与 AI 协助。
- 点击边或事件：右侧展示发生时间、原始陈述、来源、修改/删除入口。
- 教学页面：展示下一节课用到的知识点、班级证据和准备结果，可跳回学生或来源。
- 默认局部图，搜索和筛选后逐步展开，始终有等价列表；大规模网络不一次全加载。
- 新记录实际写入成功才轻微高亮节点及关系；尊重减少动态效果设置。

## 三阶段实施与验收

### 第一阶段：操作闭环与来源记录

补齐已确认的日常交互修复：名单导入预览与字段对应、统一查看/修改/删除/返回、可重新查看的失败结果、可随时停止桌面控制的紧凑入口。同时实现 Core 学生身份与关系事件的最小增量，接入现有教师观察入口。

验收：多学生一句话、同班/跨班同名、重复消息、否定与纠正、无法解析的输入；每条可展示记录都有真实来源。普通名单和记忆操作继续工作。先完成确定性写入测试，再验证真实模型对话，分别报告结果。

### 第二阶段：学生图谱与课前准备

Core 输出局部学习网络和互动投影，支持修改、撤回、筛选及分页；Desktop 实现班级与学生入口。备课检索纳入与当前课程有关的学习证据，同伴互动只用于有依据的班级活动建议。

验收：节点/边可点击，改动刷新后保留，撤回不再被检索；真实 703 数学课能从对话记录走到下一课练习或教案，并显示依据。旧记录与更新的学习表现能按时间共同查看。

### 第三阶段：持续运行与首次使用

贯通已记录、整理中、准备完成状态；新手引导串联模型配置、教师资料、名单课表导入、第一次对话记录和课前准备。利用实际数据规模测量首屏及展开性能，再决定索引优化。

验收：重启后图谱和任务继续存在；断网/模型失败可恢复；修改或删除不因重试复活；首次使用的教师能完成一条从输入到产物的流程。

## PR 与继续入口

三个阶段是产品验收阶段。涉及新 Core 合同的阶段分成 Core producer 与 Desktop consumer 配对 PR，Core 合并后更新 Desktop pin；不为凑三个 PR 把两库的改动混为一项。每个 checkpoint 写清实现、验证与未验证部分。
