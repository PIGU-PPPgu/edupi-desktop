# 教学重点对话导入设计

## 目标

教师在教学模块点击“对话补充重点”后，进入现有全局 AI 协作，使用文字或口述说明近期值得关注的知识点、共性错误、学生和推进安排。EduPi 将内容整理为教学重点候选，等待教师确认后再进入后续写回流程。

## 方案选择

采用“全局协作 + 全局口述输入”。教学模块只负责生成有上下文的首轮提示并切换到现有 Chat；聊天输入框提供口述开关，识别文本进入草稿，不自动发送。

未采用两种替代方案：

- 教学模块内嵌第二套聊天框：会复制会话、模型、草稿和附件状态，也破坏全局协作入口的一致性。
- 直接写入教学重点：当前配对 Core 未开放 subject knowledge 写入命令，不能把候选误报为已导入。

## 数据流

1. 教师点击“对话补充重点”。
2. Desktop 根据学科、年级和已有重点生成一段首轮提示。
3. EduPi 切换到全局 AI 协作，并替换输入框草稿、聚焦输入框。
4. 教师继续打字，或点击口述按钮开始/停止听写。
5. 最终识别文本追加到当前草稿；不自动发送、不直接写回。
6. Agent 将回答整理为主题、依据、关注对象和下一步候选，并明确等待教师确认。

## 交互与失败状态

- 支持 Web Speech API 时显示口述按钮；监听中使用明确的按下状态和“停止口述”标签。
- 浏览器拒绝麦克风或识别失败时，仅显示一条紧凑错误信息，保留原草稿。
- 不支持 Web Speech API 时不显示不可用按钮，文字输入保持完整可用。
- 离开或卸载输入框时中止识别，避免后台继续监听。

## 验收

- “导入教学重点”不再打开文件选择器。
- 点击后进入全局 AI 协作，草稿包含教学重点候选与教师确认要求。
- 口述结果追加到草稿且不会自动发送。
- 开始、停止、错误和卸载均能收束识别状态。
- TypeScript、相关回归、全量测试、Lint 与浏览器真实点击通过。
