# EduPi 工作区任务板实施计划 — 2026-08-30

## 目标

新增一级入口“工作区”，把现有 Core 教师任务、任务会话和教师审核状态投影成一个全宽四列看板。任务板是现有工作闭环的另一种视图，不创建浏览器本地任务状态，也不绕过 Core 回执。

## 产品决定

- 四列固定为：待处理、进行中、待我确认、已完成。
- 任务的列由现有事实自动计算：教师审核结果优先，其次是候选产物和 Agent 会话状态。
- 卡片点击进入现有任务详情；任务详情、Agent 协作、材料证据和审核继续复用当前路径。
- 第一版不提供伪拖拽或本地新建。手动拖拽和新建任务必须等 Core 提供 receipt-bound 状态命令后再做。
- 页面使用现有灰阶、细边框和紧凑排版，参考看板的扫描效率，不复制其 Git/worktree 语义。

## 分栏规则

1. 已完成：任务状态为 accepted、modified 或 rejected。
2. 待我确认：任务仍未终结，但候选内容或交付物已经形成，审核步骤处于 active。
3. 进行中：任务绑定的 Agent 会话正在运行；或已有会话且任务仍未形成候选产物。
4. 待处理：其余 planned/hold 任务，包括尚未开始和暂缓任务。

每列按日期优先、任务标识稳定排序。搜索复用顶部搜索框，匹配标题、任务类型、日期、来源节点、学生和主题。

- 点击或键盘激活卡片后进入现有任务详情。
- 工作区页面不显示对象侧栏，保留完整看板宽度。

- 一级导航“工作区”已加入协作区，URL 为 `module=tasks&view=workspace`。
- 真实投影同时读取教师任务、work-candidate 回执生命周期和任务 Agent 会话，不维护本地看板状态。

- 搜索“赵六”只保留对应任务；窄屏保持四列横向滚动，页面本身没有横向溢出。
- 卡片点击进入既有任务详情，并修复了 `view=tasks` 已选任务未渲染主工作区的旧断点。
- 1440×900 与 768×900 浏览器验证通过，控制台无 warning/error。
