# EduPi Desktop 信息架构 V2 实施计划

## 目标

把 Desktop 从“每个页面堆满解释和汇总”改成教师可操作的三层工作区：一级导航选择工作域，二级侧栏选择对象或分类，主区域只处理当前对象；详情、编辑和协作固定在右侧抽屉。

## 架构决定

- 删除全局模块顶栏；搜索、状态和动作归属到当前模块。
- 二级侧栏必须可点击，主区域不再一次展示全部对象。
- 日程使用两组正交切换：内容为“汇总 / 校历 / 课程表”，时间为“日 / 周 / 月”。
- 任务按教学准备、学生跟进、校历节点、材料证据、活动与其他分类。
- 学生名单通过配对 Core 的 `students` 操作写入唯一画像存储；Desktop 不直接写画像 JSON。导出只读，可保存当前档案或档案内成长轨迹。
- 动效只表达真实状态：正在运行、刚刚写入、记忆更新；不做装饰性粒子背景。

## Phase 1：框架、日程与任务

### 1. 删除顶部模块栏

验收：教育工作区不再渲染全局搜索/完成数/教师内部顶栏；主内容从导航栏下方直接开始。

### 2. 日程双切换与抽屉编辑

验收：可切换汇总、校历、课程表；日/周/月继续可用；点击编辑后表单直接替换右侧详情，不再出现在页面顶部；保存后保留当前抽屉和选择。

### 3. 任务分类

验收：二级侧栏显示五类任务及数量；工作区任务板可按分类过滤；同一任务只进入一个主分类。

## Phase 2：班级与学生档案

### 4. 班级主工作区

验收：学生列表全部可点击；主区显示选中学生的观察、错误模式、成长轨迹和家校联系；无选择时显示班级摘要。

### 5. 学生导入与导出

验收：导入按钮进入真实材料暂存/确认流程；导出支持当前快照 JSON/CSV，以及按档案中已有日期节点过滤；原始内部路径与哈希不出现在导出文件。

## Phase 3：教学、记忆、洞察与成长

### 6. 教学准备工作区

验收：显示下一节课、教学重点、当前材料和准备任务；支持导入教学重点材料；自动准备状态可见，未生成时可发起协作。

### 7. 教育记忆与观察洞察

验收：二级侧栏对象可点击；主区仅显示当前对象；列表超过 20 条分页；来源、时间和关联对象可追溯。

### 8. 专业成长

验收：明确分为过程文档、可复用方法、学习候选；每项都有状态与下一动作，不再显示抽象口号。

## Phase 4：待确认与运行动态

### 9. 待我确认重构

验收：分为任务、观察、记忆三类；每张卡只回答“是什么、依据、要我做什么”；审核动作与结果保持 Core 回执闭环。

### 10. 真实运行动态

验收：导航底部显示空闲/运行/刚写入三种状态；运行时轻量脉冲；写入后短暂显示“已记住”，尊重 reduced-motion。

## Checkpoints

- P1：任务 1–3，浏览器验证并提交 PR。
- P2：任务 4–5，学生导入/导出真实闭环。
- P3：任务 6–8，教学与长期积累可操作。
- P4：任务 9–10，全量测试、桌面浏览器验收与发布检查。

## 风险

- 学生导入是独立 Core bridge operation，尚未并入版本化 command/receipt 合同；当前由固定组件清单、请求上限、Core 锁和 `external_send: false` 约束。
- 学生档案的历史粒度取决于现有 trajectory/error_patterns 日期，不补造缺失时间。
- 全局顶栏删除后，模块搜索必须在二级侧栏或模块头内继续可达。
