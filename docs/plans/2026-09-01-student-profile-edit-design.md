# 学生档案编辑与响应式详情设计

## 目标

学生名单和右侧详情在宽屏上共同使用可用空间，不再让主内容固定居中并产生大片留白。教师可以直接修改学生档案，也可以把同一份学生上下文交给全局 AI 协作。

## 方案

采用“宽屏停靠、窄屏覆盖”的详情面板：

- 宽屏时详情固定在工作区右侧，宽度在 400–560px 之间；学生主界面填满剩余空间。
- 中小屏时详情覆盖主界面；移动端占满宽度。
- 主界面与详情使用同一学生选择状态，不新建页面或第二套导航。

未采用模态框，因为学生名单需要与详情并行浏览；未采用教学模块内嵌 AI，因为全局 AI 协作已经拥有会话、模型、附件、口述和草稿状态。

## 手动修改

学生详情头部提供“手动修改”和“AI 协作”。手动修改打开预填表单，允许替换：

- 学生特征；
- 家校备注。

姓名、学习模式、成长轨迹和系统生成记录本轮只读，避免把重命名误实现成新增学生或破坏来源记录。保存调用新的学生档案更新接口，Core 只替换可编辑字段，并保留错误模式、轨迹、创建时间和其他未知字段。

## Core / Desktop 数据流

1. Desktop 读取当前学生的 `updated_at`。
2. `PUT /api/edupi/students/[name]` 接受严格字段：`traits`、`parentNotes`、`expectedUpdatedAt`。
3. Desktop 调用 Core `students` operation 的 `update` action。
4. Core 校验目标存在和版本未变化，原子替换可编辑字段。
5. Desktop 重新读取教育投影并更新界面。

AI 协作只生成修改候选，教师仍可返回手动编辑器确认保存。

## 验收

- 宽屏选择学生后，主界面与详情并排，没有无效居中留白。
- 详情头部存在“手动修改”“AI 协作”“关闭”三个明确动作。
- 手动保存可以删除旧特征或旧备注，而不是只追加。
- 保存后学习模式和成长轨迹保持不变。
- 旧版本提交被拒绝并提示刷新后重试。
- Core、Desktop、配对 E2E、类型、Lint 和浏览器交互全部通过。
