# EduPi 工作台呈现决策

日期：2026-08-22
状态：已冻结为下一阶段 UI/信息架构基线

## 结论

EduPi 不再沿用“Pi Chat + 教育卡片”的主呈现方式。EduPi 采用两种产品范式的组合：

- **NomiFun 范式**：桌面级、持久化、项目/工作区中心的工作台外壳；一级导航、二级对象树、主工作面、上下文选择、工具/自动化/设备按需进入。
- **TabTin 范式**：任务是第一公民；一个任务包含人类目标、Agent 执行过程、持久产物、检查清单、评审/协作状态和可继续的任务输入。

这不是复制两个项目的代码或品牌，而是迁移交互模型。TabTin 使用 AGPL-3.0-only，NomiFun 使用 Apache-2.0；EduPi 只借鉴产品范式，避免把参考仓库代码直接混入现有 MIT 项目。

## EduPi 的目标界面

```text
教师打开 EduPi
→ 进入“我的教育工作台”，不是空聊天
→ 选择学校 / 年级 / 班级 / 学科上下文
→ 在任务树中选择一个教学任务
→ 在主工作面提出目标或打开已有任务
→ EduPi Agent 执行并展示可展开的步骤
→ 生成持久化材料 / 证据 / 课程产物
→ 教师在检查清单和证据面板中核对
→ 接受、修改、暂缓、拒绝或撤销
→ 任务和产物可继续、回看、引用和协作
```

## 四层信息架构

### 1. 一级导航：教育工作台

普通教师看到的是教育对象，不是开发者工具：

- 工作台
- 教学任务
- 材料与证据
- 课程与校历
- 班级与学生
- 教学产物
- 待审核

Models、Skills、Plugins、MCP、运行时和调试入口降为设置/管理员层，不作为教师主导航。

顶部提供：

- 全局搜索：任务、学生、材料、产物、证据、课程节点；
- 当前教育上下文：学校、年级、班级、学科；
- 新建任务 / 导入材料 / 打开最近任务；
- 当前保存状态和本地运行状态。

### 2. 二级导航：教育工作区和任务树

不要再以 Pi session 列表作为教师的主要历史入口。改为持久化对象树：

```text
学校
└── 学段 / 年级
    └── 班级
        ├── 学科 / 单元
        │   ├── 教学调整任务
        │   ├── 作业错因任务
        │   └── 课堂记录任务
        ├── 课程与校历
        └── 班级 / 学生跟进
```

Pi session 仍保留，但作为任务内 Agent 协作记录或管理员调试对象，不作为教师首页的第一对象。

### 3. 主工作面：任务时间线 + 教育产物

任务页面采用 TabTin 的结构化时间线，而不是只有聊天消息：

1. 教师目标 / 原始请求；
2. Agent 角色和当前执行状态；
3. 可展开的执行步骤；
4. 引用的材料和事实来源；
5. 产物卡片；
6. 质量检查清单；
7. 教师反馈和版本变化；
8. 可继续输入框。

底部输入框是“任务续写/操作台”，支持：

- 继续任务；
- 选择教育 Agent 角色；
- 选择受控动作；
- 引用材料、证据或产物；
- 上传新材料；
- 请求教师复核。

聊天只是任务时间线中的一种交互，不再独占主界面。

### 4. 右侧上下文面板：证据、属性和审核

右侧面板可展开/收起，显示当前任务或产物的：

- 事实来源和文件路径；
- 材料哈希 / 版本；
- 推断状态；
- `scope`、`externalSend`、`requiresTeacherReview`；
- 生成规则和 Agent 执行记录；
- 审核历史；
- rollback 入口；
- 关联课程、班级和学生。

教育安全边界固定为：

```text
scope=teacher_internal
externalSend=false
requiresTeacherReview=true
inference_status=candidate_only
```

## 两种工作模式

### A. 教师任务模式：TabTin 风格

适合：

- 作业错因核对；
- 下一节课调整；
- 课堂记录整理；
- 校历节点准备；
- 学生跟进；
- 教研材料评审。

核心对象是 Task，必须有：

```text
目标
来源
Agent 执行过程
产物
检查清单
教师审核
反馈
版本 / rollback
```

### B. 教学工作面：NomiFun / Creative Studio 风格

适合：

- 单元/课程设计；
- 多份材料并排比较；
- 课件、练习、错因图谱和证据组织；
- 需要持续编辑的教学产物。

初期不做复杂自由画布。先做可持久化的教育工作面：

```text
左侧：单元 / 任务 / 产物结构
中间：材料、文本、表格、证据和版本
右侧：选中对象属性、来源和审核
底部：插入材料、问题、检查项、Agent 动作
```

后续再增加节点/画布能力，不能用画布取代任务和审核。

## 产品对象映射

| 参考范式 | EduPi 对象 |
| --- | --- |
| NomiFun Sessions | 教学任务和任务历史 |
| NomiFun Projects / Workspaces | 学校、年级、班级、学科工作区 |
| NomiFun Desktop Companions | 教育 Agent 角色：学科助教、班主任协作、教务整理 |
| NomiFun Knowledge / Assets | 教师材料、证据和教学产物库 |
| NomiFun Workshop / Canvas | 课程/单元教学工作面 |
| NomiFun Scheduled Tasks | 校历节奏和教师内部准备任务 |
| TabTin Agent task | EduPi 教学任务 |
| TabTin execution details | Agent 执行步骤和可核验日志 |
| TabTin artifact | 教学产物 / 证据包 / 检查清单 |
| TabTin review group | 教师审核、教研协作和受控评审 |

## 对当前代码的直接影响

下一阶段不再继续给 `EduPiEducationHome.tsx` 添加首页卡片。优先顺序改为：

1. 新增工作台壳层和一级教育导航；
2. 新增持久化教育 Workspace / Task / Artifact 的 UI 契约；
3. 将现有 onboarding、校历、材料、审核模块迁入对应工作区；
4. 将 Pi Chat 降为任务内 Agent 协作面；
5. 将证据/审核/rollback 做成右侧上下文面板；
6. 最后再拆 `AppShell` 和 `SessionSidebar`，避免在旧信息架构上继续重构屎山。

现有 safe store、`calendar.json`、`timetable.json`、`teaching.json`、`class.json`、`student_profiles.json` 和 `rhythm_plan.json` 继续复用，不建立第二套事实数据库。

## 验收标准

新呈现方式至少满足：

- 首屏是教育工作区，不是空聊天；
- 教师能从工作区树进入一个具体任务；
- 任务能显示 Agent 过程、来源、产物、检查项和审核状态；
- 材料和产物是可回看、可引用、可版本化的持久对象；
- 右侧面板能解释“这是什么、依据什么、谁审核、能否撤销”；
- 普通教师不需要配置 Models / Skills / Plugins；
- 真实写回仍经过 safe store 和教师审核边界；
- 浏览器验证区分代码、隔离 fixture、真实本地数据和真实教师证据。
