# 班级计算

初始实现基于 Desktop `a9f10da6` 和固定 Core `9a26adb8`，保留在 `codex/core-classroom-20261113`。2026-11-17 的配套集成从 Desktop `c19cd15d` 与 Core `64930d5d` 主线派生，只迁移本轮算法与接线，保留主线的分页设置、学生班级档案、Main4 和写者准入。实际固定版本以 `contracts/edupi-core-compat.json` 为准；严格版本常量、兼容清单及 Core 官方生成的两份组件清单一起更新，保留当前 Bridge v1.1 和日程 v1.2 身份。

## 数据与调用

`班级 → 成绩分析 / 排座与分组 / 值日排班` 和 AI 工具 `edupi_classroom` 调用 `classroomService`，经既有 Desktop bridge 进入 Core `classroom` operation。`roster/list/read/preview` 为读取或纯计算，`save/restore/begin_publish/link_task` 经过 writer admission 与文件锁。Main4 中的写入还需要既有 owner control 授权，值日任务创建只接受 Core 已预留的方案身份。计算在 Core 运行，不请求模型。AI 使用原 EduPi 模型配置，仅解释工具返回值及协助录入。

学生来自正式 `student_profiles.json`，只传稳定 ID、姓名、班级及教师录入的特征。成绩文件读取复用现有名单文件解析器，支持 CSV、TSV、Excel；工作表、表头、姓名列和科目列由教师核对，文件预览不写学生档案。未知或同班同名学生必须人工匹配，显式 ID 优先，不跨班按姓名降级匹配。文件中的明确来源班级会传入 Core 并保留；与所选班级冲突时拒绝计算结果和保存，显式 ID 也不能绕过。多个班级列要求教师先保留权威列。

正式对象保存在 Core 数据根 `.edupi/memory/classroom_objects.json`，每个对象有稳定 ID、领域、输入、程序结果、版本、时间及修改记录。修改携带 `expected_revision`，保存重新计算并回读；重复操作返回原版本回执，版本已被后来修改时不伪称当前回读一致。恢复历史输入后重新计算，产生新版本，保留原记录。

值日方案使用稳定任务 ID `duty-<方案ID>`，任务详情反向打开同一份 Core 方案。关联前先在 Core 持久预留，追加版本并固定名称、班级和日期范围，再创建或核对已有任务，最后反链并追加修改记录；中断可按原始版本恢复，重试不重复创建。预留和关联后仍可调整岗位与值日人；名称、班级和日期范围另建方案。任务中不复制容易过期的完整排班。

## 成绩口径

来源为 Headteacher-helper `f174c28d6459ede8f709fff9639fdbd9beb7ba9a` 的 `src/grade-engine/` 和 `src/grade-analysis/`，各算法文件保留来源注记与摘要。没有引入其页面、存储、云端账号、CloudBase 或 aiProxy。

- 缺考为 `null`，不计零；不完整总分不参与总分排名。
- 标准差为样本标准差，分母 `n−1`；竞争排名为 `1,1,3`。及格线为满分 60%，优秀线为 85%；无有效分数时比例为空。
- 跨考只按已确认的稳定学生 ID 取共同学生与共同科目，在该共同群体中分别标准化。不同满分显示警告、百分制及 Z 分变化，不把原始分差解释为难度校准后的提升。
- 学生增值残差为 `Z出口 − β×Z入口`，`β=max(原回归系数,0.8)`；班级平均残差乘 `n/(n+15)`。结果不外推为全年级增值或因果效果。
- 不沿用原九段与 `A+/A` 指标冲突，也不把人数阈值叫作统计显著性检验。

## 排座与分组口径

比较了 `Seating.tsx`、`DesktopConsole.tsx`、`SeatSwapAssessment.ts` 与 `studentGender.ts`。统一采用移动端较完整的风险画像、邻座惩罚与学习层次互补，保留共同的性别归一及配对语义；成绩通过同班 Core 考试引用，未知性别不猜测。

| 项目 | 采用规则 |
| --- | --- |
| 人数与容量 | 全部参与 ID 恰好出现一次；明确组容量，不产生空组；修复移动端丢弃奇数余员、桌面端挤占六人组 |
| 画像 | 教师明确录入的活跃、自管、情绪稳定、领导力及成绩信息；不从学生姓名推断 |
| 性别 | 异性优先、同性优先或不限制，均为偏好；接回配对函数的 `rest` |
| 硬约束 | 固定座位、首排、分离、座位容量及小组容量；不静默放宽 |
| 手动调整 | 交换学生或移入空座后，用同一程序检查当前完整布局；有硬错误不得保存 |
| 计算上限 | 最多 100 名学生、30 行、20 列、200 个座位，每组最多 6 人；搜索共享 2 秒、500 万工作量和 60,000 节点预算，耗尽明确报错，不把未知可行性写成成功 |

`row/column` 内部从 0 开始，界面从 1 开始；小组编号从 1 开始。性别策略不等于强制人数条件，提示与硬约束错误分别展示。

## 值日口径

来源为 `cloud/apiCore/dutySchedule.js` 的岗位分配、周内加权负担平衡及跨周游标。保留日历周语义，支持 1–35 天和选择排班星期。

岗位含人数、权重、性别要求；名单、免值日、每日岗位上限及每周天数上限由教师配置。人数必须为整数，未知性别不匹配限定性别岗位。人手不足保留明确错误，不突破免值日或岗位限制填满。

人工调整和替班使用同一验证；链式 `A→B→C` 按顺序执行，岗位与当日名单保持一致，最终负担按实际分配重新统计。自动分配增加后续岗位及整数学生日容量预判，避免先平均摊开便耗尽每周可用天数。公平性是周内加权平衡和跨周轮换，没有实现按历史实际完成量补偿，不宣称长期劳动公平；该算法不是通用完备求解器。
