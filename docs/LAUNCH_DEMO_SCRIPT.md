# EduPi 明日 3 分钟演示脚本

## 0:00–0:25｜EduPi 是什么

“EduPi 是教师的本地智能工作台。它把校历、课程、学生材料和 AI 协作放在同一个桌面里，让教师从‘找事情、抄事情’转向‘确认事情’。”

## 0:25–0:45｜为什么做

“教师每天最耗时的往往不是教学判断，而是把通知、表格、材料重新整理成日程和任务。EduPi 的目标，是提前完成这些行事历工作，把最后决定留给教师。”

## 0:45–1:15｜首次进入

1. 打开 EduPi，输入邀请码。
2. 新手教程出现，依次展示“连接模型”“确认教师资料”“进入今天”。
3. 点击“模型设置”，指出它复用桌面端现有模型配置，不另建账户体系。
4. 返回后打开“教师资料”，展示称呼、学科、年级已经成为 AI 协作上下文。

讲述：“设置只做一次；以后从帮助可以随时重开。”

## 1:15–2:05｜文件变成行事历

1. 进入“校历”，上传学校通知、校历图片或文件。
2. 展示识别出的日期候选与来源。
3. 点击一个日程项，打开右侧详情。
4. 强调日期不确定时停在待确认，不静默写入。

讲述：“老师给 EduPi 的仍是日常文件，EduPi 把它整理成可以检查的日程，而不是要求老师重新录入。”

## 2:05–2:40｜今天与协作

1. 回到“今天”，展示由校历和材料形成的待办。
2. 打开一个任务，查看证据、进度与产物。
3. 进入协作，询问：“根据我的七年级数学安排，今天先准备什么？”
4. 指出回答已经带入教师资料，不再重复追问身份。

讲述：“桌面端是 EduPi 的可见部分；真正目标是它提前把教师今天要处理的事情准备好。”

## 2:40–3:00｜收束

“EduPi 不替教师作最后决定。它负责理解材料、组织时间、准备任务；教师负责确认、修改和发布。”

## 失败降级

- 模型暂不可用：直接展示已准备好的“今天”、校历和任务详情，不现场重试；说明本地资料仍可浏览。
- 文件识别失败：切换到已导入的校历样例，明确说明失败可见、不会生成假日期。
- Core 未就绪：打开管理中心的就绪状态，不演示写入；使用预先录制的 30 秒本地视频完成流程展示。
- 网络不稳定：使用本地安装版和预置数据；GitHub Release 页面只作为最后的下载说明展示。
